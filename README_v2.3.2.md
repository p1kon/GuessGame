## Главное изменение

**Версия 2.3.2 не меняет ни математические модели предсказателя, ни ИНР.** Она снижает риск утраты ручной истории и делает диагностику воспроизводимой.

1. Повреждённое старое сохранение переносится в уникальный карантин до перезаписи; если архивировать его не удалось, перезапись запрещена.
2. Ошибка `localStorage` больше не оставляет незавершённый ход: данные сохраняются в памяти текущей вкладки, отображается предупреждение с возможностью повтора или экспорта.
3. Сброс выполняется транзакционно: сначала успешная запись пустого состояния, затем изменение текущего состояния.
4. Для экономии места в `localStorage` полный диагностический снимок (`expertProbs`, `expertWeights`) сохраняется на каждом 50-м ходе и на последнем; **все биты, фактически показанные прогнозы, P(1), времена, счётчики и текущие обученные модели сохраняются на каждом ходе**. Полная диагностика остаётся в памяти до закрытия или перезагрузки страницы, поэтому при необходимости экспортируйте JSON **до закрытия вкладки**. Уже прореженные старые диагностические снимки восстановить нельзя.
5. В «Проверить модели» теперь видны все 16 экспертов, включая `markov1`; вычисление идёт по снимку истории, не изменяющемуся во время долгого расчёта.
6. Рядом с экспортом добавлена команда «Архив восстановления» — выгрузка сырых строк браузерного хранилища, включая карантины. Такой архив предназначен для ручного восстановления, **не** для прямого импорта.

## Перед первой игрой в 2.3.2

1. Откройте предыдущую версию и сделайте **экспорт JSON**. Храните файл отдельно.
2. Откройте `GuessGame_v2.3.2.html` в браузере. Если старая история не обнаружилась (например, из-за отличий `file://`-хранилища), импортируйте JSON через **replace**.
3. Проверьте значение счётчиков: исходная историческая копия содержит **1200 ходов, 758 угадываний**. Если продолжали играть после того экспорта, сравните с актуальной копией.
4. После серии игр снова выгрузите JSON. При предупреждении о несохранённых ходах **не закрывайте вкладку**, пока не сохраните экспорт; при необходимости нажмите «Повторить сохранение».

## Эксперименты

- ИНР остаётся v0.2 с прежними 8 параметрами; случайные числа не подмешиваются.
- Доступны `baseline`, `slow`, `fast`, `multi`, сравнение целей G, батарея разработки и резерв.
- Для контрольного прогона: `I=.9, S=.7, M=10, C=.25, Q=.5, E=.6, D=.7, G=-1`, 600 ходов, сессия 100, стартовый бит 0, `baseline` на новом предсказателе. Результат: **413/600 (68,83%)**.
- **Не изменяйте версию приложения посреди серии сравнимых испытаний.** Сохраняйте конфигурации, версии и экспорт лаборатории для каждого условия.
- Резервную батарею не используйте для подгонки новых алгоритмов; искусственный противник не заменяет проверки на свежих человеческих ходах.

## Ограничения

`localStorage` остаётся конечным и зависит от браузера. Прореживание расширяет практический ресурс, но не устраняет квоту. При отказе записи приложение не может гарантировать сохранение данных после закрытия вкладки; именно поэтому есть предупреждение и ручной экспорт. Разные локальные HTML-файлы могут получать раздельные области хранения. Архив `quarantine` не следует удалять без ручной резервной копии.

Подробности и мотивировка решений приведены в `CODE_DOCUMENTATION_v2.3.2.md` и `RELEASE_DECISIONS_v2.3.2.md`.
