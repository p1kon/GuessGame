# Решения по внешнему ревью — релиз v2.3.2

**Статус:** выпуск для следующей серии экспериментов, заморожен 12 ноября 2026 года.  
**База:** полученные `CODE_REVIEW_v2.3.md`, `REFACTORING_NOTES_v2.3.1.md`, `GuessGame_v2.3.1.html`.  
**Принцип:** не менять алгоритмы 16 предсказателей, эталонного Fixed-Share Hedge, альтернативных агрегаторов и ИНР v0.2.

## Принято и включено

| Код замечания | Решение | Обоснование |
|---|---|---|
| R1 | **Усилено**: отдельные последовательно нумеруемые карантины для сырых повреждённых записей; если запись в карантин невозможна, основная запись **не перезаписывается** | Версия 2.3.1 сохраняла только первый повреждённый файл; повторный сбой или переполнение могли уничтожить второй |
| R2 | **Принято с явным компромиссом**: в постоянной записи полная диагностика экспертов через 50 ходов + последний, а все ключевые фактические сведения сохраняются на каждом ходе | Сокращение расхода квоты. В отличие от кратких научных сведений, детальные исторические снимки после перезагрузки не гарантируются |
| R3 | **Принято**: при сбое записи модель завершает ход в RAM, UI показывает несохранённые данные, предлагает повтор и экспорт; сброс транзакционный | Не блокируем игрока и не имитируем обратную операцию над PPM/CTW/SGD |
| R4–R6 | **Принято из 2.3.1**: корректная версия файла экспорта, защита повторного бенчмарка, явный `labelMode` | Устранение конкретных UI-дефектов |
| R7–R11 | **Принято из 2.3.1**: мёртвые структуры, общий PPM trace, именованные константы и чистка параметров | Упрощение кода без изменений прогнозирования; эквивалентность проверена |
| R12 | **Принято и расширено**: показывать **все 16** экспертов в walk-forward-таблице, а не только часть; фиксировать копию истории на время асинхронных абляций | Полнота научной диагностики и стабильность сравнений |
| R13 | Оставлен стиль от 2.3.1, без дополнительных косметических переписываний | Минимизировать риски релиза |

## Отложено / не принято в этом цикле

| Предложение | Решение | Почему |
|---|---|---|
| Полный перенос хранения в IndexedDB | **Отложено** | Для текущей серии достаточно компактного localStorage и экспорта; большая асинхронная миграция увеличивает риск. Обсудить после замеров на продолжительной ручной истории |
| Полная долговременная запись 32 экспертных чисел на каждом ходе | **Не сохранять в localStorage в v2.3.2** | Приоритет — безопасность и длина ручной истории; детальный журнал можно экспортировать до закрытия вкладки, кроме ранее прореженной истории |
| Кэширование walk-forward и абляций | **Отложено** | Улучшение скорости, не корректности; нужна стратегия инвалидирования при новых ходах/импорте |
| Разделение на `engine.js`/`ui.js` с процедурой сборки | **Отложено** | Поддерживать автономный HTML в течение экспериментов; возможна сборка отдельных исходников в один HTML позднее |
| Сокращение числа экспертов по абляциям | **Отклонено в этом цикле** | Это изменение научной модели и нарушит сопоставимость; позже после заранее заданного протокола сравнения |
| Новый детектор смены стратегии и новые η | **Отклонено в этом цикле** | Пока исследуем имеющиеся 4 агрегатора, сохраняя исходный эталон |
| Новые схемы истинного holdout | **Отложено** | Открытые резервные сценарии полезны, но главный независимый тест — будущая реальная человеческая история |
| Имитация реального браузера роботом и HTTP API | **Отклонено как ненужное сейчас** | Разделение движка и симулятора уже обеспечивает точность и скорость |

## Что именно НЕ менялось

- Список и формулы всех 16 предсказателей, PPM, CTW-подобной модели, SGD.
- Весовые обновления эталонного Fixed-Share Hedge, варианты slow/fast/multi.
- Алгоритм выбора битов ИНР v0.2, восемь параметров, эмоции и правила сессий.
- Реальный бинарный прогноз фиксируется до ответа игрока; реактивный игрок не знает текущий прогноз.
- Структура схемы ручного JSON (`schemaVersion = 2.1`), типы форматов лаборатории, изоляция ручной истории.

## Что намеренно изменилось

- Метаданные версии и имена новых файлов экспорта — `2.3.2`.
- Только способ **сохранения** развёрнутого журнала, не данные прогноза в памяти и не алгоритм обучения.
- Действия пользователя в случае сбоев хранилища и сброса.
- Дополнения в диагностике интерфейса и её защита от параллельного изменения истории.

## Пройденные проверки выпуска

1. Узлы `PredictorEngine` из 2.3.1 и 2.3.2: 32 новых хода поверх исходных 1200, точное совпадение прогнозов, вероятностей, признаков и весов, PPM/CTW/SGD.
2. ИНР v0.2 + baseline: 600 ходов (6 сессий) — идентичны побитово, **413/600** угадано.
3. Многоскоростной агрегатор `multi` при трёх внешних установках G: совпадение 300-ходовой истории, метрик и весов с 2.3.1.
4. Walk-forward на той же истории: сохранена метрика ансамбля и `markov1`.
5. Прореживание: проверено сохранение каждого бита, бинарного прогноза, P(1), времени, метаданных; JSON проходит `validatePayload`.
6. Повторное повреждение: две различные сырые строки попали в два разных карантина.
7. Квота: при невозможности создать карантин старая повреждённая запись осталась без изменения; при невозможности записать backup основная осталась прежней.
8. Headless Chromium: ручной ход, принудительный отказ сохранения, продолжение хода, экспорт, успешный повтор, восстановление из сохранённой записи, транзакционный сброс при отказе записи, загрузка сырого архива, все 16 экспертов в таблице, лабораторный прогон 60 ходов. Ошибок JS нет.

**Регрессионный скрипт:** `verify_release_v2.3.2.js` (использует Node.js и исходные `GuessGame_v2.3.1.html`, `GuessGame_v2.3.2.html`, `guessGameState_2026-11-08 (3).json`). Браузерный тест `browser_test_232.py` предназначен для среды разработчика с установленным Playwright.

## Известные риски и правила следующей серии

- Нельзя обещать вечное сохранение после превышения квоты: экспорт JSON остаётся обязательной страховкой.
- Диагностические массивы экспертных прогнозов/весов в персистентном журнале **разрежены**; основной проверяемый прогноз и P(1) не разрежены.
- Если `localStorage` недоступен полностью, приложение может работать только до закрытия вкладки; при ошибке записи не закрывайте её без экспорта.
- Сессии, ограниченные искусственными временными метками, не равны психологическим сессиям человека.
- Сравнение агрегаторов — разных замкнутых взаимодействий с ИНР, а не парный тест по одним битам.
- Реальный случай 1200/758 — историческая контрольная точка, но не заменяет последующие независимые реальные ходы.

## Критерий заморозки

Исходный HTML и документация публикуются с SHA-256 в `SHA256SUMS.txt`. Во время следующей серии **не редактировать эти файлы**; при любой функциональной правке выпускать новую версию и повторять тесты.
