# Исходная точка и этап 0

Дата проверки: 2026-11-14. Исходный commit: `9ef0c345814113b586bdae9b0bc5b9299aa9743d`. Локальная метка эталона: `baseline-v2.3.2`. Рабочая ветка: `infrastructure/baseline-tests`.

## Проверено

- Семь сценариев исходного `verify_equivalence.js` прошли при сравнении HTML из handoff-архива и репозитория с внешним историческим JSON.
- Историческое состояние восстанавливается как 1200 ходов / 758 угадываний. Сам файл остаётся вне проекта.
- Контрольная симуляция ИНР v0.2: 600 ходов, шесть сессий, 413 угадываний.
- Сохранены 16 экспертов и агрегаторы baseline/slow/fast/multi.
- После усиления сравнения полного сериализованного состояния повторно выполнены синтетическая и приватная регрессии.

## Отличия от handoff

`README_v2.3.2.md` и полная документация совпадают побайтово. Скрипт проверки совпадал после нормализации CRLF/LF. В журнале выпуска исправлено имя регрессионного скрипта. В HTML перед стилями присутствует внешний скрипт Kaspersky, отсутствующий в архиве; вычислительный код совпадает. Это означает, что репозиторный HTML не является побайтовой копией архивного. Он сохранён без правок и закреплён отдельной контрольной суммой; выполнение внешнего скрипта и его доступность не входят в регрессию ядра.

## Изменения инфраструктуры

Добавлены инструкции и контекст из handoff, правила игнорирования приватных файлов, контрольные суммы четырёх релизных артефактов, тесты Node.js без зависимостей и workflow GitHub Actions. Workflow проверен локальными командами; удалённый запуск произойдёт после публикации ветки.

В `verify_equivalence.js` исправлена имитация localStorage; удалён путь к чужому локальному JSON. Без явного файла создаётся синтетическая история с фиксированными битами и временем. Добавлена абсолютная проверка 413/600. Сравнение продолжения теперь включает полное сериализованное состояние (в том числе PPM/CTW и forecastLog), а Map распознаются между VM-контекстами. Ожидаемое отличие — только инфраструктура проверок; фактическое поведение игры неизменно.

## Ограничения и следующий этап

Браузерный `browser_test_232.py` упомянут в прежней документации, но не включён в комплект. Новые тесты хранения исполняют настоящие функции через VM с имитацией localStorage; они не заменяют проверку интерфейса в браузере. Транзакционный UI-сброс и ошибки DOM пока не проверяются автоматически. Серверных callback, базы данных и многопользовательского сервиса пока нет.

Следующий этап — выделение ядра в модули с сохранением автономного HTML, затем сравнение с закреплённым эталоном на обеих категориях входных данных. Математика предсказателей, ИНР и агрегаторов заморожена. Публичный пилот и детали модели хранения не утверждены этим инфраструктурным этапом.

## Уточнение байтов исходного Git-эталона при публикации

Первоначальный аудит выполнялся на рабочей Windows-копии: Git с core.autocrlf=true преобразовал строки HTML в CRLF. При публикации восстановлены неизменённые байты HTML из коммита 9ef0c34 (SHA-256 `35f2e867c3390a46de5fa6739f38078339076854c9222128920844a0259955b2`). Текст после нормализации окончаний строк совпадает. Контрольные суммы baseline/checksums.json теперь относятся к исходным Git-байтам; остальные три артефакта и их суммы не менялись. Прежняя Windows-копия сохранена приватно. Это уточнение упаковки, без изменения алгоритмов или интерфейса.
