# Ограниченные снимки модели и очистка Git-истории

Версия приложения: `storage-preview-1`. Алгоритм предсказателя 2.3.2, ИНР v0.2 и схема базы v4 сохранены.

## Хранение модели

Раньше после каждого хода сохранялся полный снимок со всей растущей историей, без удаления предыдущих. Это приводило к примерно квадратичному росту хранимых данных.

Теперь на одного участника остаются не более пяти полных снимков:

- начальный снимок с ревизией 0;
- актуальный и предыдущий;
- два последних доступных контрольных снимка с ревизиями, кратными 100, не предшествующих импортированной предыстории.

Совпадающие ревизии учитываются один раз. При небольшом числе ходов снимков может быть меньше пяти. Новый снимок, результат ответа, квитанция и удаление устаревших производных снимков фиксируются одной транзакцией. Ошибка удаления откатывает весь ответ, сохраняя незавершённый прогноз для повтора. Текущий повреждённый снимок по-прежнему блокирует работу; явное восстановление использует исходный журнал.

Не удаляются биты, исходные snapshots прогнозов, вероятности и голоса экспертов в событиях, времена, показанные прогнозы, квитанции, сессии, данные привязки, записи импорта, отдельные replay-training snapshots и recovery_audit. Исходные события остаются доказательством фактически сыгранной игры. Формулы обучения и прогнозы не меняются.

Полное текущее состояние всё ещё сериализуется после каждого ответа. Ограничен объём сохраняемых версий; это не устранение всей стоимости вычислений и записи на очень длинных историях. После удаления старых строк SQLite переиспользует свободные страницы; физический размер существующего файла сокращается отдельным VACUUM.

## Обслуживание существующей базы

Остановите обе службы бота и веба. Активная аренда бота блокирует обслуживание; остановка веба также обязательна. Инструмент сам делает согласованную проверенную резервную копию.

```bash
# Проба на отдельной копии, рабочая база не меняется:
TELEGRAM_DB_PATH=/path/to/game.sqlite BACKUP_DIRECTORY=/private/backups \
  node scripts/compact-database.mjs

# Применить после остановки обеих служб:
TELEGRAM_DB_PATH=/path/to/game.sqlite BACKUP_DIRECTORY=/private/backups \
  node scripts/compact-database.mjs --apply
```

Проверяются полное восстановление каждой модели, побайтовый JSON-экспорт состояния и контрольная сумма всех логических таблиц кроме производной predictor_snapshots. После сокращения снимков и VACUUM проверки повторяются; дополнительно выполняются integrity_check и foreign_key_check. Приватный отчёт показывает число снимков, объём JSON и размер файла до/после, путь и SHA-256 резервной копии. Резервные копии и отчёты не публикуются.

Тесты покрывают границы контрольных снимков, предел пять, точное совпадение с непрерывным движком на 305 ходах, перезапуск с незавершённым прогнозом, импорт, независимость игроков, транзакционный отказ удаления, повреждённое состояние второго участника, пробу на копии и физическое сокращение файла.

## Git-история

По разрешению владельца личный JSON удалён git-filter-repo из всех публикуемых веток и затронутой метки. Коммит эталонной v2.3.2 сохранён. Новые деревья исходников совпадают с прежними; изменились только ссылки и история после загрузки JSON. Полная прежняя история хранится исключительно в игнорируемом приватном Git bundle.

Старые клоны нельзя сливать обратно в очищенную историю: они могут вернуть удалённый файл. Для другого компьютера предпочтителен новый клон с переносом только нужных незакоммиченных файлов и приватной конфигурации. Не импортируйте в Git приватный резервный bundle.

GitHub сохраняет отдельную read-only ссылку закрытого PR №1 на старый коммит. Force push веток и меток её не удаляет. Подготовлен приватный запрос владельца в GitHub Support на удаление cached views/PR refs и сборку мусора. До обработки этого запроса нельзя утверждать, что все старые копии данных на GitHub недоступны. Независимые клоны и форки также не удаляются переписыванием основного репозитория.

Для предотвращения повторной публикации добавлена `npm run check:public` и проверка CI с полной историей веток/меток. Она блокирует приватные пути, базы/ключи, характерные токены и JSON-истории без явной маркировки искусственного fixture. Это дополнительный защитный барьер, не доказательство отсутствия любого возможного секрета.
