# Перенос прежней истории в Telegram

Административный импорт добавляет историю из ручного JSON перед уже записанными Telegram-ходами того же человека. Он не предназначен для объединения данных разных участников. Публичной кнопки импорта нет.

## Протокол

1. Бот должен быть остановлен, незавершённый ход — отвечен. Активная аренда polling или ожидающий ход блокируют перенос.
2. Скрипт выбирает единственного разрешённого участника по локальному `.env`. Если их несколько, нужен `--user=числовой_ID`.
3. До миграции рабочей БД создаётся согласованная резервная копия через SQLite VACUUM INTO, включающая зафиксированные данные WAL. Копия проверяется `integrity_check` и SHA-256.
4. Отдельная копия используется для пробного импорта и полного восстановления по событиям. Исходная резервная копия остаётся неизменной.
5. `--apply` применяет тот же результат к рабочей БД одной транзакцией. Контрольная сумма текущего снимка должна совпадать с состоянием до резервирования. Повтор того же импорта не добавляет ходы второй раз; другая история при уже выполненном импорте отвергается.

```powershell
# Пробный перенос: рабочая база не изменяется
npm.cmd run telegram:import -- 'C:\path\to\state.json'

# Перенос после остановки бота
npm.cmd run telegram:import -- 'C:\path\to\state.json' --apply
```

Резервные копии, пробные БД и отчёты находятся рядом с рабочей базой в `private/backups/`; они не публикуются в Git. Этот архив содержит реальные данные. Удаление через бота не удаляет отдельно сделанные резервные копии и исходный JSON.

## Как сохраняется достоверность данных

Исторический JSON восстанавливает исходное состояние предсказателя, а не просто число ходов. Сохраняются имеющиеся веса, PPM/CTW/SGD, биты, прогнозы и метаданные. Отсутствовавшие сведения о старых прогнозах не придумываются: legacy остаётся legacy.

Для уже сыгранных Telegram-ходов обучение пересчитывается по расширенной предыстории. Их исходные `turns.snapshot_json`, биты, время, seq, контрольные суммы, фактически показанные прогнозы и результаты не переписываются. Новые учебные snapshots хранятся отдельно в `turn_training_snapshots` с `origin: replay`. Они не выдаются за показанные человеку прогнозы. Для response-моделей в историю обратной связи поступает именно прежний показанный прогноз, даже если новая модель вычислила бы другой.

Счёт равен сохранённому историческому счёту плюс фактическим результатам Telegram. Пересчёт обучения не добавляет задним числом успешные угадывания. В объединённом состоянии `history`, `predictions`, `moveTimes`, `forecastLog` сохраняют обе части истории. Старые номера Telegram-ходов не меняются; следующий новый seq равен общему числу ходов плюс один, поэтому в серверном журнале возможен скачок номера.

`history_imports` хранит исходный JSON с SHA-256, прежнее начальное состояние и полное состояние до переноса. Новый базовый снимок становится точкой восстановления. Проверка recovery отдельно сверяет исходные события и пересчитанные учебные snapshots; восстановление должно побитово совпадать с импортированным состоянием. Все сведения импорта включены в личный экспорт. Подтверждённое удаление участника очищает и записи импорта из рабочей БД.

Для новых участников импорт не выполняется автоматически. Формулы 16 экспертов, агрегаторов и ИНР не меняются. После переноса нужен обычный запуск бота и `/stats`, затем `/resume`.
