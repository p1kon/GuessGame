# VPS: серверный запуск GuessGame

Версия размещения: `web-preview-1`. Алгоритм остаётся 2.3.2, схема БД — v4. Ubuntu 24.04 LTS x86-64, Node.js 26.13.1. Для Node 26 на минимальном образе требуется `libatomic1`.

## Размещение

| Назначение | Путь |
|---|---|
| Текущий код | `/opt/guessgame/current` |
| Релизы | `/opt/guessgame/releases` |
| Node.js | `/opt/guessgame/node/bin/node` |
| Приватная конфигурация | `/etc/guessgame/guessgame.env` |
| База и WAL/SHM | `/var/lib/guessgame/telegram.sqlite*` |
| Ежедневные резервные копии | `/var/backups/guessgame` |

Бот выполняется от непривилегированного системного пользователя `guessgame`. Код принадлежит root, приватные файлы доступны службе. systemd задаёт абсолютный TELEGRAM_DB_PATH; поэтому относительный путь, сохранённый в перенесённом `.env`, не используется.

## Управление через SSH

```bash
sudo systemctl status guessgame --no-pager
sudo systemctl status guessgame-web --no-pager
sudo journalctl -u guessgame -n 30 --no-pager
sudo systemctl restart guessgame
sudo systemctl stop guessgame
sudo systemctl start guessgame-backup
sudo systemctl list-timers guessgame-backup.timer
```

`guessgame.service` включён в автозапуск, перезапускается при ошибке через 20 секунд. После аварии может потребоваться истечение двухминутной аренды polling; лимит перезапусков учитывает это. Обычный SIGTERM завершает long polling и освобождает аренду. Firewall разрешает входящий SSH на 22, исходящие соединения разрешены. Nginx обслуживает веб по HTTPS на 443; порт 80 используется для ACME и перенаправления. Веб-приложение слушает только 127.0.0.1:3000. Продление сертификата проверяет guessgame-cert-renew.timer дважды в сутки.

На ноутбуке больше не запускайте `npm.cmd run telegram:start` с тем же токеном: два компьютера с разными копиями БД не должны одновременно обрабатывать обновления. Локальная база после переноса — архивная копия и не синхронизируется автоматически с VPS.

## Резервирование

`guessgame-backup.timer` запускается ежедневно около 03:00 UTC с задержкой до 15 минут. Сохраняются последние 14 успешно проверенных автоматических копий. SQLite VACUUM INTO включает зафиксированные изменения WAL без остановки бота. Каждая копия проверяется integrity_check, foreign_key_check и SHA-256. Удаляются только автоматически созданные файлы со строго заданным именем, после создания новой валидной копии.

Службе резервирования разрешена запись в каталог БД для служебных WAL/SHM; сам файл открыт readOnly. Первую серверную копию скачали в игнорируемый `private/backups/vps/` на ноутбуке и проверили полным восстановлением модели по событиям. Регулярное автоматическое внешнее резервирование ещё не настроено: ежедневные копии пока находятся на том же VPS. До расширения пилота нужно выбрать независимое хранилище и срок удаления его копий.

Для восстановления остановите бота и guessgame-web, сохраните нынешнюю БД, разверните выбранную согласованную резервную копию без старых WAL/SHM, восстановите права guessgame:guessgame/0600, выполните `scripts/verify-database.mjs` с нужным TELEGRAM_DB_PATH и только затем запустите службу. Примените удаления участников, случившиеся после даты резервирования. Подробности секретов не должны попадать в журнал или Git.

## Проверки переноса

- Согласованная исходная база содержит 1230 ходов; её SHA-256 сверена после передачи.
- На VPS прошли 35 публичных тестов; два теста с локальным историческим JSON пропущены.
- Реальная перенесённая модель проверена полным replay по исходным событиям, включая импорт прежней истории.
- Перезагрузка VPS выполнена; бот и таймер резервирования поднялись автоматически, SSH и firewall работают.
- Проверенная серверная резервная копия скачана на ноутбук и восстановлена до тех же 1230 ходов.

Математика, исходные ходы и показанные прогнозы не менялись. Полные снимки после каждого хода всё ещё увеличивают расход диска; переход к ограниченному числу контрольных снимков остаётся следующим инженерным этапом. Уведомления о сбоях вне journal/systemd и регулярные внешние копии пока не реализованы.
